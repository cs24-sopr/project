# 84. Skill und CLI für wöchentliche Statusberichte

## Hintergrund und Zielstellung

Jedes Teilteam muss wöchentlich einen Statusbericht für das gemeinsame
Semesterprojekt abgeben. Das manuelle Anlegen der MDX-Dateien führte
gelegentlich zu Formatierungsabweichungen, unvollständigen Ticketlisten
oder Verzögerungen bei der Einreichung.

Mit Issue #84 wurde ein automatisierter Workflow geschaffen:
- Auslesen der abgeschlossenen und aktiven GitHub Issues je Teilteam.
- Einheitliche Formatierung gemäss `vorlagen/team-update.mdx`.
- Automatische Erkennung von Folgesprint, Kalenderwoche und Sidebar-Position.
- Striktes Verbot von Halluzinationen (gezieltes Nachfragen bei Unklarheiten).
- Bereitstellung als CLI-Werkzeug und als Agent-Skill.

---

## 1. CLI-Skript: `scripts/create_weekly_status.py`

Das Skript wertet GitHub Issues aus und generiert die passende MDX-Datei
im Teamordner (`docs/content/project/statusberichte/<team>/`).

### Unterstützte Funktionen
- Automatische Ermittlung der nächsten Sequenznummer (Sprint/KW).
- Abfrage der GitHub Issues über das `gh` CLI anhand des Teamlabels.
- Übernahme konkreter Issue-IDs (`--issues 61,62,73`).
- Interaktiver Modus (`--interactive`) mit Rückfragen bei fehlenden Feldern.
- Vorschau ohne Schreibzugriff (`--dry-run`).
- Einhaltung der maximalen Zeilenlänge von 80 Zeichen.

### Aufruf und Parameter

```bash
# Bericht im Trockenlauf prüfen
python3 scripts/create_weekly_status.py --team builder --dry-run

# Bericht interaktiv erstellen (fragt bei Unsicherheiten nach)
python3 scripts/create_weekly_status.py --team coding --interactive

# Bericht mit festen Parametern anlegen
python3 scripts/create_weekly_status.py \
  --team assets \
  --sprint 2 \
  --kw 45 \
  --status yellow \
  --author "Aljoscha Burger"
```

## 2. Agent-Skill: `/weekly-status-report`

In `.agents/skills/weekly-status-report/SKILL.md` ist der Workflow
für KI-Agenten hinterlegt.

### Grundregel: Nachfragen statt Halluzinieren
Der Agent darf bei fehlenden oder mehrdeutigen Angaben (z. B. Ampelstatus,
Blocker, Schnittstellenänderungen) keine Annahmen erfinden, sondern muss
den Nutzer direkt im Dialog um Klärung bitten.

Einfach `/weekly-status-report` aufrufen oder den Agenten bitten:

`python3 scripts/create_weekly_status.py --team <team> --interactive`

Bei Fragen wendet euch gerne an das Orga-Team!
